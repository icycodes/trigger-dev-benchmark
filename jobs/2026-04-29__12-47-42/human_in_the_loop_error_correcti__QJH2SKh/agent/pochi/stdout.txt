# Durable Error Recovery with Human-in-the-Loop ## Background Trigger.dev's durable execution allows workflows to pause and wait for external input without consuming compute resources. This is particularly useful for building resilient pipelines that require human intervention when an automated step fails or requires manual correction. ## Requirements * Initialize a Trigger.dev project in `/home/user/resilient-pipeline`. * Implement a child task `unreliable-task-${trial_id}` that: * Accepts a payload `{ input: string, shouldFail: boolean }`. * If `shouldFail` is true, it throws an error: `"Simulated failure: ${input}"`. * Otherwise, it returns `{ result: `Processed: ${input}` }`. * Implement a parent task `resilient-pipeline-${trial_id}` that: * Accepts an initial payload `{ input: string }`. * Triggers `unreliable-task-${trial_id}` with `{ input: payload.input, shouldFail: true }` (forcing an initial failure). * Catches the error from the child task. * Creates a waitpoint token using `wait.createToken()`. * Writes the token ID to `/home/user/resilient-pipeline/waitpoint_token.txt`. * Pauses execution using `wait.forToken()`. * The token completion payload will be `{ correctedInput: string }`. * Once the token is completed, it triggers `unreliable-task-${trial_id}` again with `{ input: completion.output.correctedInput, shouldFail: false }`. * Returns the final result from the second child task call. * Suffix all task IDs with the `trial_id` read from `/logs/trial_id`. ##
