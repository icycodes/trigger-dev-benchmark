## How It Works

1. The queue enforces a global limit of 10 concurrent executions across all users
2. When triggering tasks, the `concurrencyKey` is set to `user:{userId}` for each task
3. Tasks with the same `concurrencyKey` (same user) will execute sequentially (1 at a time)
4. Tasks with different `concurrencyKey`s (different users) can execute in parallel
5. This ensures that one user's heavy workload doesn't block other users while still limiting individual user resource consumption
